# FrostLens 的研究定位与验证路线

FrostLens（霜镜）面向 NH₃/CO₂ 复叠制冷研究，把一个常被忽略的问题放在计算结果旁边：**功率曲线拟合得很好，是否真的意味着压缩机效率、换热能力和辅助功耗被数据区分开了？下一次测什么，才能减少这种不确定性？**

项目把两回路物性计算、灰箱参数估计、局部可辨识性诊断、竞争参数解释和下一次实验推荐连接起来。使用者可以从合成案例开始，观察不同参数如何产生相近功率，再增加一条虚拟测量，检查解释是否分开。虚拟实验是可重复的学习和软件验证工具，不是现场实验的替代品。

## 为什么选择这个方向

复叠中间温度优化已有长期研究基础：2006 年的研究分析了蒸发温度、冷凝温度和复叠温差对最优中间温度的影响；随后已有 NH₃/CO₂ 实验系统的性能研究 [1–2]。因此，再做一张 COP 曲线或运行一次优化，不足以形成鲜明的项目价值。

值得补上的环节是结论的证据：模型中的哪些参数能被现有测量确定，哪些只是在彼此补偿？新工况增加的是重复数据，还是新的区分能力？相关超低温冷柜灰箱研究已经指出低可辨识性会限制参数解释 [3]。这支持本项目的问题意识，但不能直接证明某个具体复叠系统也存在相同程度的问题。

这个方向连接三个研究活动：

- **灰箱建模：**让参数估计与参数可信度同时可见，避免只用训练误差评价模型。
- **热流体实验设计：**在用户规定的候选范围和测量噪声假设下，比较改变温度、负荷或增加测量通道能带来多少信息。
- **CFD：**未来可用局部流动与换热计算检验等效 UA 的工况依赖性，或构造多保真模型。当前版本没有 CFD 求解器、CFD 校准、网格无关性验证或 CFD 数据接口；等效 UA 也不能解释局部流场。

## 与已有开源工具的关系

| 工具 | 已提供的能力 | FrostLens 的位置 |
| --- | --- | --- |
| CoolProp [4] | 热物性数据库及状态量接口 | 直接使用其物性能力，补充研究工作流；不重写状态方程 |
| TESPy [5] | 组件网络、设计与非设计点求解、制冷案例及优化 | 聚焦小型复叠案例的参数证据与实验选择；不替代通用热系统仿真 |
| PyBaMM / PyBOP [6–7] | 电池模型的敏感性、参数估计与设计优化 | 借鉴清晰的模型—数据—推断工作流，面向不同的物理系统 |
| Pyomo.DoE [8] | 基于模型的实验设计、Fisher 信息与多种最优准则 | 将成熟方法包装为制冷研究者易用的案例、图形反馈和可复算报告 |

以上是基于公开文档的定位比较，不是穷尽检索，也不意味着这些工具无法通过扩展实现类似功能。研究者可以直接使用它们完成更复杂的任务。

## 创新在哪里，边界在哪里

本项目追求的是**领域问题与交互工作流的原创组合**：不只展示一个最优拟合，而是寻找差异较大的竞争参数解释；不只说“数据不足”，而是给出能检验这些解释的候选工况；不只追求更多数据，而是比较同样实验预算下的数据价值。通过“有限次数实验排除错误解释”的交互，使严肃的方法可以被直观探索。

物性计算、蒸气压缩循环、灰箱估计、奇异值分析、Fisher 信息和 D 最优设计都不是本项目提出的新理论。热泵压缩机的最优实验设计也已有公开研究 [9]。因此不使用“全球首创”“首个可辨识性工具”或“已证明最省实验”的表述。当前新意主要体现为面向这一具体系统的可运行实现、案例组织、可解释反馈与复现体验；能否成为新的研究方法，取决于后续对比和真实数据证据。

当前模型及输出还需按以下方式理解：

- NH₃ 与 CO₂ 分属两个回路；不是两种制冷剂的混合物模型。模型采用简化稳态循环及等效参数，完整假设以实现和报告为准。
- 局部 Jacobian 的奇异值描述指定参数点、参数尺度与噪声模型附近的信息；不能替代全局或结构可辨识性证明。
- 推荐分数依赖模型、候选集合、参数估计和噪声假设。正则项用于数值计算时必须显示，不能被解释为新测量已经带来的信息。
- 找不到第二组参数不等于解唯一；找到第二组近似解释也不等于两者在所有工况等价。
- 残差异常说明数据与当前假设可能不一致，不足以单独确定设备故障。模型没有通过真实设备诊断验证。

## 需要真实实验回答的问题

**问题一：有限温度与负荷范围内，只测总功率能否区分两级效率、UA 和辅助功耗？** 比较局部信息、重复拟合的参数稳定性及独立工况预测，而不是只比较训练误差。

**问题二：同样预算下，推荐工况是否比常规取点更有用？** 预先登记候选范围、初始数据、总预算和评价指标，再执行顺序实验。推荐不能越过台架运行边界；软件中的物性可行性检查不等同于设备许可工况。

**问题三：模型结构不够准确时，推荐能否保持价值？** 例如效率随压比变化、UA 随负荷变化、传感器偏差或动态未稳定。应分别评估参数不确定性与模型偏差；更小的局部参数不确定性不保证更准的外推。

建议建立三组基线，使用相同初始数据和评价集：

1. **取点基线：**随机可行取点、温度/负荷均匀覆盖，与顺序 D 最优推荐比较；随机策略报告多次重复的分布。
2. **测量基线：**仅总功率，与总功率加低温级功率比较；增加仪表的费用和测量时间单独计入，不能只按数据行数宣称更省成本。
3. **解释基线：**仅报告一个最佳拟合，与报告竞争参数和局部信息比较；另用包含未建模机制的测试情景检验提示是否有帮助。

建议同时记录实验次数、有效稳态采集时间、切换与稳定等待时间、仪表成本以及推荐计算耗时。效果指标包括独立工况功率 RMSE、噪声归一化误差、参数跨重复实验的稳定性，以及达到预先规定预测误差所需的预算。真实未知参数没有“恢复真值”指标；仅合成数据可计算参数恢复误差。若未来增加区间估计，还应报告覆盖率，而不是只展示区间变窄。

## 数据划分与防止信息泄漏

按独立实验批次、运行日期或完整工况分块留出验证集，避免把同一稳态段的相邻采样随机拆到训练与测试中。初始辨识、实验推荐、阈值选择和调参不能读取最终测试数据。跨温区外推与同温区重复实验应分开报告。

合成演示中，同一模型生成再拟合的数据只能检验理想条件下的恢复能力；应另设结构失配情景。虚拟实验的隐藏参数不能参与拟合或候选排序，固定种子应随报告保存。真实导入数据与合成数据必须保留明确来源，不能把虚拟测量追加为真实记录。

记录物性与软件版本、输入单位、数据摘要和划分规则。若总功率与分项功率来自同一组仪表计算，两通道误差可能相关；使用独立噪声假设前必须检查，后续可增加协方差加权。温度和负荷的测量误差也是未来误差模型的重要组成部分。

## 路线图与贡献入口

- **当前原型：**打通简化双回路模型、合成案例、数据导入、拟合诊断、候选推荐和结果导出；具体交付以 README 与测试为准。
- **台架验证：**发布允许公开的匿名数据、仪表信息与划分规则，复现实验预算对比，记录推荐无效或模型失配的反例。
- **方法扩展：**参数剖面或重复采样不确定性、多参数点稳健实验设计、相关误差与输入误差、实验切换成本，以及明确设备边界的候选管理。
- **更广系统：**在验证后加入动态模型、TESPy 适配或 CFD 支持的 UA 关系；不将路线图功能写成当前能力。

社区最有价值的贡献包括：可公开的失败案例、独立热力学基准、带测量不确定度的数据、数据校验改进、复算教程与易用性反馈。提交数据前应确认有公开权利；仓库不需要包含私人研究材料才能演示完整流程。
